# Q1 ONNX Motion Tracking 推荐部署流程

本文档描述从机器人上电到执行 ONNX motion tracking 的推荐流程。核心原则：

```text
官方高层运控负责起身/站稳
ONNX 脚本只负责站稳后的 motion tracking
不要让官方高层运控和 ONNX 低层关节控制同时接管
```

## 方式一：推荐，用官方 STAND_UP 起身

### 1. 机器人上电

确认机器人处在官方正常模式，高层运控可用。此时不要启动 ONNX 低层控制脚本。

### 2. 用官方高层起身

使用官方 `SetMcAction` 或 example 让机器人走状态机：

```text
PASSIVE_DEFAULT -> STAND_UP -> BIPED_STAND_DEFAULT
```

如果使用官方 `mc_locomotion_velocity.py`，它可能继续切到：

```text
BIPED_WALK_RUN
```

这也能说明机器人已经站稳，但我们真正需要的是稳定站立初态。更理想的是停在 `BIPED_STAND_DEFAULT`。

### 3. 人在旁边保护

官方 `STAND_UP` 过程中，人站在机器人旁边保护，不要硬拉关节。站起来后确认：

```text
身体基本竖直
脚底正常接触地面
没有明显晃动
没有异常报警
```

### 4. 停止官方高层控制输入

如果用了 `mc_locomotion_velocity.py`，确认它已经停止发速度并释放 input source。不要让它继续控制机器人。

### 5. 切到低层开发/低层控制模式

ONNX 脚本使用的是低层关节控制接口：

```text
/aima/hal/joint/command
```

官方文档要求：使用低层关节控制前，必须关闭高层运控模块。否则高层控制和低层关节命令会抢控制权，可能导致震颤或异常保护。

### 6. 人继续扶住机器人，先 dry-run

先不开电机，只检查 policy、topic、IMU 和状态链路：

```bash
cd ~/q1_asap_2real
source /path/to/q1_ros2_ws/install/setup.bash

python scripts/sim2real_q1_motion_tracking_ros2.py \
  --config config/q1_sim2real_base.yaml \
  --policy-path policies/lateral_raise/model_6000.onnx \
  --motion-file motions/lateral_raise/lq1_ateral_raise.pkl \
  --urdf robots/q1/q1_22dof_box.urdf \
  --robot-yaml robots/q1/q1_22dof.yaml \
  --enable-policy \
  --dry-run
```

观察日志，确认：

```text
state=HOLD_CURRENT
cycle_time 正确
policy_dt=0.0200s (50Hz)
joint_age 正常刷新
base_age 正常刷新
静止时 projected_gravity 接近 [0, 0, -1]
ONNX input 是 [1, 365]，output 是 [1, 22]
```

如果 `projected_gravity` 明显不接近 `[0, 0, -1]`，优先检查 IMU 坐标系、四元数顺序和 topic 类型，不要开电机。

### 7. 启动 ONNX 电机模式，但先不执行 policy

关闭 dry-run，开电机。第一次建议使用更保守的插值参数：

```bash
python scripts/sim2real_q1_motion_tracking_ros2.py \
  --config config/q1_sim2real_base.yaml \
  --policy-path policies/lateral_raise/model_6000.onnx \
  --motion-file motions/lateral_raise/lq1_ateral_raise.pkl \
  --urdf robots/q1/q1_22dof_box.urdf \
  --robot-yaml robots/q1/q1_22dof.yaml \
  --enable-policy \
  --enable-motors \
  --risk-confirm I_UNDERSTAND_REAL_ROBOT_RISK \
  --get-ready-duration-s 5.0 \
  --max-command-step-rad 0.005
```

启动后脚本应进入：

```text
WAIT_STATE -> HOLD_CURRENT
```

`HOLD_CURRENT` 的含义是：保持当前关节角，不运行 ONNX policy。它不是平衡站立控制器。

### 8. 人扶着机器人，按 `i`

按 `i` 后进入：

```text
GET_READY
```

脚本会把当前关节角缓慢插值到训练默认姿态 `default_dof_pos`。这一步不是起身，只是站姿对齐。

观察：

```text
腿方向是否正确
膝盖是否轻微弯曲
脚底是否大致平
上身是否竖直
有没有抖动
command_step 是否逐渐变小
base_ang_vel 是否接近 0
```

不要马上松手。可以在保护下慢慢让机器人承重，确认它不是一落地就歪。

### 9. 按 `a`

进入：

```text
POLICY_ARMED
```

这一步只是准备 policy，还没有执行动作。

### 10. 按 `p`

进入：

```text
POLICY
```

开始 ONNX motion tracking。

第一次建议从风险低的动作开始：

```text
stand_still -> lateral_raise -> bolt -> football/shoot
```

注意：policy 和 motion 必须是一对。不能只换 motion，不换对应 ONNX。

### 11. 异常处理

异常时立刻按：

```text
q
```

脚本会进入：

```text
EMERGENCY_DAMPING
```

同时应准备外部急停或人工保护。

## 方式二：不用官方 STAND_UP，只靠人工/吊装

这种方式风险更高，只适合台架、吊装或有人持续保护的检查流程。

流程：

```text
1. 机器人上电
2. 人把机器人提起或吊起，使身体接近竖直
3. 切到低层开发模式
4. 启动 ONNX dry-run，检查 IMU 和 joint state
5. 启动 ONNX 电机模式
6. 等脚本进入 HOLD_CURRENT
7. 按 i，让关节插值到 default_dof_pos
8. 不要马上松手，慢慢让脚接触地面
9. 确认可以承重、无明显抖动
10. 按 a
11. 按 p
```

这里的 `i` 不能让机器人自己从地上站起来。它只是把关节摆到默认角度。身体姿态、防倒和承重过渡需要人或吊装负责。

## 禁止流程

不要这样做：

```text
机器人瘫倒在地
-> 直接启动 ONNX
-> 按 i
-> 按 p
```

也不要这样做：

```text
官方 BIPED_WALK_RUN / BIPED_STAND_DEFAULT 仍在控制
-> 同时启动 ONNX 低层 /aima/hal/joint/command
```

这两种情况都可能导致控制冲突、异常震颤或硬件风险。

## 按键说明

```text
i = 插值到默认站立位姿
 a = 进入 POLICY_ARMED
p = 开始执行 ONNX policy
o = 停止/保持当前位置
q = 紧急阻尼
```

## 一句话总结

```text
先用官方高层或人工/吊装把机器人变成“已经竖直、接近站稳”的状态，
再切低层，让 ONNX 脚本 HOLD_CURRENT，
然后按 i 对齐默认姿态，
最后 a/p 执行动作。
```
